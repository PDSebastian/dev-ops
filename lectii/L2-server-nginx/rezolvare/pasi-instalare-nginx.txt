NGINX CA REVERSE PROXY - PASI DE INSTALARE
platforma: compose-platform.yaml (L1), 5 aplicatii + MySQL comun


PASUL 1 - context path la fiecare aplicatie

In compose-platform.yaml, la fiecare serviciu adaugi in environment
prefixul pe care il va folosi nginx:

  sebionlineschool-app:
    environment:
      SERVER_SERVLET_CONTEXT_PATH: /school

  sebi-onlineshop-app:
    environment:
      SERVER_SERVLET_CONTEXT_PATH: /shop

  car-app:
    environment:
      SERVER_SERVLET_CONTEXT_PATH: /cars

  boats-users:
    environment:
      SERVER_SERVLET_CONTEXT_PATH: /boats

  solar-sync-app:
    environment:
      - SERVER_SERVLET_CONTEXT_PATH=/solar

Nu reconstruiesti nicio imagine. Variabila se citeste din mediu, la fel ca
DB_URL. Atentie la solar-sync-app: acolo environment e lista, deci sintaxa
este "- CHEIE=valoare", nu "CHEIE: valoare".

De aici inainte Swagger nu mai este la /swagger-ui/index.html, ci la
/school/swagger-ui/index.html. Un 404 dupa pasul asta inseamna ca prefixul
isi face treaba, nu ca s-a stricat ceva.


PASUL 2 - aplicatiile numai pe loopback

Tot in compose-platform.yaml, pui 127.0.0.1: in fata fiecarui port publicat:

  ports:
    - "127.0.0.1:8084:8083"     school
    - "127.0.0.1:8085:8084"     shop
    - "127.0.0.1:8087:8086"     cars
    - "127.0.0.1:8091:8086"     boats
    - "127.0.0.1:8082:8081"     solar

Numerele raman exact cele care merg acum. Se schimba doar interfata pe care
asculta Docker: de la "toate" la "numai masina asta".

La mysql stergi complet liniile ports si - "3307:3306". Aplicatiile ajung la
baza pe reteaua interna, dupa numele serviciului (mysql:3306).

    docker compose -f compose-platform.yaml down
    docker compose -f compose-platform.yaml up -d
    docker compose -f compose-platform.yaml ps

CRITERIU DE GATA - rulat PE SERVER:

    curl -I http://127.0.0.1:8084/school/swagger-ui/index.html
    curl -I http://127.0.0.1:8085/shop/swagger-ui/index.html
    curl -I http://127.0.0.1:8087/cars/swagger-ui/index.html
    curl -I http://127.0.0.1:8091/boats/swagger-ui/index.html
    curl -I http://127.0.0.1:8082/solar/swagger-ui/index.html

Cinci raspunsuri 200. Daca unul nu raspunde, opreste-te aici - nginx nu are
ce sa proxeze. 127.0.0.1 inseamna mereu "masina de pe care tastez", deci de
pe laptop nu ai cum sa verifici serverul asa.


PASUL 3 - instalare nginx

    sudo apt update
    sudo apt install -y nginx
    systemctl status nginx

CRITERIU DE GATA: active (running), iar in browser http://18.232.176.158/
afiseaza "Welcome to nginx!". Daca browserul se invarte, e portul 80 inchis
in Security Group, nu nginx.


PASUL 4 - urci configuratia

De pe laptop, cu WinSCP sau scp, pui platform.conf in ~ pe server. Apoi:

    sudo mv ~/platform.conf /etc/nginx/sites-available/platform
    sudo ln -sf /etc/nginx/sites-available/platform /etc/nginx/sites-enabled/platform
    sudo rm /etc/nginx/sites-enabled/default
    sudo nginx -t && sudo systemctl reload nginx

rm default: altfel portul 80 este revendicat de doua ori si pe / iti raspunde
tot "Welcome to nginx!".

nginx -t &&: daca testul pica, reload-ul nu se mai executa si ramai pe
configuratia veche, care merge.

reload, nu restart: reload ridica worker-i noi cu configuratia noua si ii
lasa pe cei vechi sa termine cererile in curs.

CRITERIU DE GATA: nginx -t spune syntax is ok / test is successful.

PASUL 6 - inchizi usile din spate

EC2 - Security Groups - grupul instantei, exact doua reguli inbound:

    SSH    22    My IP
    HTTP   80    Anywhere-IPv4

Stergi tot ce este pe 8082, 8084, 8085, 8087, 8091 si 3307.

CRITERIU DE GATA - de pe laptop:

    curl -sS -m 5 http://18.232.176.158/school/swagger-ui/index.html
    curl -sS -m 5 http://18.232.176.158:8085
    curl -sS -m 5 http://18.232.176.158:3307

Prima trebuie sa intoarca HTML. Ultimele doua trebuie sa dea eroare, refused
sau timeout. Daca raspund toate trei, lectia este instalata, nu facuta.


CAND CEVA NU MERGE

502 Bad Gateway
    nginx merge, containerul nu raspunde. Pe server:
    curl 127.0.0.1:<port>/... si docker compose ps

404 pe Swagger
    prefixul din location nu este identic cu SERVER_SERVLET_CONTEXT_PATH

"Welcome to nginx!" pe /
    nu ai sters sites-enabled/default

browserul se invarte
    Security Group, nu nginx. Timeout = firewall, refused = nu asculta nimeni

configuratie buna, dar nu se aplica
    ai uitat reload

    sudo tail -f /var/log/nginx/error.log
    docker compose -f compose-platform.yaml logs -f sebionlineschool-app


DE RETINUT

Portul din proxy_pass este portul din stanga din ports:, cel de pe host.
nginx ruleaza pe server, nu in Docker, deci vede aplicatiile prin
127.0.0.1:<port_host>, nu prin numele serviciului.

IP-ul public se schimba la fiecare Stop/Start al instantei. Se rezolva cu
Elastic IP.
